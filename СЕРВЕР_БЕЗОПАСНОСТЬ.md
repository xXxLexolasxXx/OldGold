# Безопасность кооп-сервера OldGold (аудит 21.10.2026)

Что проверено: `server/server.js`, `simhost.js`, `errors.js`, `events.js`, `telemetry.js`, `stats.js`, `install.sh`, `js/coop/coopsim.js`, `js/coop/coopclient.js`, `tools/reports.js`, `PRIVACY.md`. Сервер в интернете: `wss://151-252-107-75.sslip.io` (Caddy → `127.0.0.1:8787`, служба `oldgold` под пользователем `oldgold`).

Проверка: `node tests/fuzz-server-test.js` (входит в `tests/run.js`). Тест запускает сервер и шлёт ему злонамеренные запросы. На коде до правок он падал на первом же запросе (`GET /%E0%A4%A`); если этот запрос убрать, находил ещё 19 провалов. После правок проходит.

Серьёзность: **Критично** — любой человек из интернета без входа роняет или ломает сервер; **Высокая** — может любой игрок (регистрация бесплатная), вред остаётся в мире; **Средняя** — флуд, обход лимитов, утечки, XSS при особых условиях; **Низкая** — защита в глубину.

## Проверено, проблем нет

- Обход путей в статике: `path.normalize` + `relative` + запрет `server/`, `.git`, точечных файлов и `coopsim.js`. Fuzz проверяет `%2e%2e%2f`, `..%5c` и `../.git`.
- `/stats` закрыт ключом (`timingSafeEqual`, 18 случайных байт). `/coop-info?metrics|digest` доступен только с loopback без XFF.
- Права хоста: `restart`, `newworld`, `setperm`, `setdiff`, `speed`, `goalmode`, `stats` проверяют `c.isHost`. Хост — это loopback без XFF (на VPS таких нет) или ник из `OLDGOLD_ADMIN`. `xgrow` работает только при `OLDGOLD_STRESS=1`.
- CORS `*` на `/e`, `/err`, `/t`, `/report`, `/coop-info`: cookie и учётных данных нет, ответы ничего не раскрывают, так что это допустимо.
- Пароли: scrypt с солью на аккаунт; токены входа хранятся как sha256, по 5 последних на аккаунт.
- `npm audit`: зависимостей нет (package.json без `dependencies`, lock-файла нет), проверять нечего. Сервер написан на чистом Node 22.
- `simhost.js` выполняет только файлы игры из репозитория; строки клиента в `vm` не передаются: карта нового мира идёт через `__mapText` и `meParse`, а не через склейку кода.

## Осталось (не исправлено в коде)

- **Средняя, конфигурация.** Хост определяется как «loopback без X-Forwarded-For». Если в Caddy когда-нибудь уберут XFF (`header_up -X-Forwarded-For`) или поставят другой прокси без него, **все** игроки станут хостами (перезапуск, новый мир). Caddyfile не трогать; при смене прокси проверить `welcome.host` у обычного игрока.
- **Средняя.** Админ по нику (`OLDGOLD_ADMIN`): если этот ник ещё не зарегистрирован, его может занять кто угодно и получить права хоста. Проверить: `node -e "console.log(Object.keys(require('/var/lib/oldgold/players.json')))"`.
- **Низкая.** Клиент игры (не только кооп) рисует часть зеркала мира через innerHTML. Злой сервер, подставленный через `?server=`, теоретически найдёт ещё место для XSS. Варианты: подтверждать чужой адрес из `?server=` или добавить CSP через `<meta>` в `index.html` на GitHub Pages (сейчас CSP есть только у страниц, которые раздаёт VPS).
- **Низкая.** Ключ `/stats?key=` передаётся в адресе и попадает в журнал Caddy (если он включён) и в историю браузера. Не публиковать ссылку; при утечке удалить `stats.key` и перезапустить службу.
- **Низкая.** Пароль от 3 символов, токены входа без срока жизни. На закрытой бете допустимо.
- **Низкая.** `/t/forget` синхронно перечитывает все файлы `telemetry/*.jsonl` (лимит 5 раз в 10 минут с адреса). При гигабайтах статистики это заметная пауза цикла.

## Рекомендации для VPS (сам на VPS не заходил)

1. **Песочница systemd.** В `server/install.sh` добавлены `CapabilityBoundingSet=`, `PrivateDevices`, `ProtectKernel*`, `ProtectControlGroups`, `RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX`, `RestrictNamespaces`, `RestrictSUIDSGID`, `LockPersonality`, `SystemCallArchitectures=native`, `UMask=0077`, `LimitNOFILE=4096`. Применятся при следующем `install.sh`. Без переустановки: `sudo systemctl edit oldgold`, вставить эти строки в `[Service]`, затем `daemon-reload` и `restart` (только при online=0). Проверка: `systemd-analyze security oldgold` (цель — ниже 3.0). `MemoryDenyWriteExecute` не включать: ломает JIT V8.
2. **Память.** Ограничить `MemoryMax=` примерно до 70 % ОЗУ VPS (например, `700M` при 1 ГБ), чтобы утечка не уронила SSH и Caddy.
3. **Права файлов.** `chmod 700 /var/lib/oldgold && chmod 600 /var/lib/oldgold/{players.json,stats.key,stats.json}`. Владелец — `oldgold`. `/opt/oldgold` должен принадлежать root и быть недоступен на запись пользователю `oldgold` (`ProtectSystem=strict` это и так обеспечивает).
4. **Сеть.** `ufw status`: открыты только 22, 80, 443; порт 8787 снаружи закрыт (служба слушает `127.0.0.1`). Проверить снаружи: `curl -m5 http://151.252.107.75:8787/coop-info` должен не ответить.
5. **SSH.** Только ключи: `PasswordAuthentication no`, `PermitRootLogin prohibit-password` (лучше отдельный пользователь с sudo), `fail2ban` для sshd.
6. **Обновления.** `unattended-upgrades` для пакетов безопасности; Node 22 LTS обновлять через `apt` (nodesource).
7. **Журналы.** Ограничить journald (`SystemMaxUse=200M`). Если в Caddy включён журнал доступа, не хранить в нём query string (там ключ `/stats`).
8. **Бэкап.** `/var/lib/oldgold` (world.json, players.json, village.json) раз в сутки копировать вне VPS: потеря диска уничтожит мир и аккаунты.
9. **Деплой этих правок.** Как обычно, при online=0: `git pull` и `systemctl restart oldgold`, затем проверить `curl -sI https://151-252-107-75.sslip.io/ | grep -i content-security` и войти в кооп с GitHub Pages.
