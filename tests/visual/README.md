# Визуальные тесты

`tests/visual-test.js` открывает игру в Chrome (Playwright, без окна), снимает ключевые экраны
и сравнивает их с эталонами в `tests/visual/ref/`. Ловит то, что не видят тесты без браузера:
кресты над домами, перекрытия панелей, белые полосы, кривые руки призрака, меню за краем экрана.

## Запуск

```bash
cd tools/browsers && npm ci            # один раз: playwright-core (браузер — установленный Chrome или Edge)
node tests/visual-test.js              # сравнить с эталонами (~5–6 минут); то же: npm run test:visual
node tests/visual-test.js --update     # переснять все эталоны
node tests/visual-test.js --update --only boss-desk   # переснять один кадр
node tests/visual-test.js --only sprite               # только кадры, в имени которых есть «sprite»
```

Флаги: `--tol 0.2` — допуск, % отличающихся пикселей (по умолчанию 0.2);
`--pix 40` — насколько должен отличаться пиксель, чтобы считаться другим (сумма |dR|+|dG|+|dB|+|dA|, по умолчанию 40).
Другой браузер: переменная `VT_CHROME=путь/к/chrome`.

Код выхода: 0 — всё совпало, 1 — есть отличия, 2 — тест не запустился.

## Что снимается

| Кадр | Что на нём |
|---|---|
| `menu-<размер>` | стартовое меню |
| `game-<размер>` | первые секунды свободной игры (обучение и сюжетная вставка — как видит новичок) |
| `panel-<размер>` | нижняя панель / вкладка «Строить» на телефоне |
| `building-<размер>` | окно жилого здания |
| `hire-<размер>` | окно мастерской, блок «Работник» (найм) |
| `sound-<размер>` | открытое меню звука ♪ |
| `boss-<размер>` | ночной бой с Курганным князем: сам босс, полоса здоровья, подсказка фазы |
| `malgor-<размер>` | реплика Малгора (сюжетное окно) |
| `*-en` | английская локаль: меню, игра (ПК и телефон), окно здания (ПК) |
| `sprite-ghost/reaper/skeleton/golem` | листы спрайтов: настроения, кадры, варианты жнеца, виды голема |

Размеры: `desk` 1280×800 (ПК), `port` 390×780 (телефон, портрет), `land` 844×390 (телефон, альбом).

## Если тест упал

Для каждого отличающегося кадра в `tests/visual/out/`:
- `<кадр>.png` — как выглядит сейчас;
- `<кадр>.diff.png` — серый снимок, красным — отличающиеся пиксели.

Если изменение **намеренное** (новая графика, поправили панель) — пересните эталон:
`node tests/visual-test.js --update --only <кадр>` и закоммитьте новый `ref/<кадр>.png` вместе с правкой.
Если нет — это баг.

## Почему снимки одинаковые от прогона к прогону

- **Время**: поддельные часы Playwright (`context.clock`) — `Date`, `performance.now`, таймеры и
  `requestAnimationFrame` стоят и идут только шагами по 100 мс, когда тест их двигает. Дата фиксирована
  (15.01.2026 12:00 UTC). Часы ставятся на контекст до init-скрипта: часы на `page` в новом документе
  стартуют с дрейфом 1–5 мс, и `setTimeout(startGame, 30)` попадает то до, то после кадра меню.
- **Загрузки**: после каждого шага часов тест ждёт в реальном времени, пока закончатся сетевые запросы и
  загрузка картинок `new Image()` — поэтому расписание не зависит от скорости машины.
- **Случайность**: `Math.random` заменён генератором с фиксированным зерном до загрузки скриптов игры
  и пересевается в контрольных точках (меню, старт игры, перед каждым кадром), поэтому мир, гномы
  и имена каждый раз те же.
- **Анимации**: CSS-анимации выключаются при съёмке (`animations: 'disabled'`), курсор ввода скрыт.
- **Хранилище**: `localStorage` чистый, язык задан явно; значок версии скрыт (меняется каждое обновление).
- **Рендер**: `--disable-gpu`, sRGB, без субпиксельного сглаживания шрифтов, `deviceScaleFactor: 1`.

Эталоны зависят от машины (шрифты, версия Chrome). Если после обновления Chrome «поплыли» все кадры
сразу на доли процента — пересните эталоны целиком (`--update`).

## Память

Один браузер на весь прогон; на каждый размер — своя вкладка, закрывается сразу после него.
Не запускать параллельно с `tools/browsers/run.js` и долгими прогонами.
