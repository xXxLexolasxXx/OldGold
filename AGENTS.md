# OldGold: графические изменения

Перед созданием, изменением или проверкой графики прочитать [GRAPHICS_RULES.md](GRAPHICS_RULES.md). Эти требования действуют для всех связанных задач: единый pixel-art стиль, полные модели, пять самостоятельных видов и восемь направлений, все родные анимации, проверка наслоений, настоящий игровой масштаб и согласованные UI-портреты.

Звери входят в графический проход по указанию пользователя. Текущую очередь видов и паузы сверять с реестром. Сохранённое и опубликованное автоматически не удалять и не откатывать. Смешанные наборы предварительно классифицировать с ведущей. Принятые гномьи головы и низкие колпаки сохранять.

Обязательно прочитать [GRAPHICS_COORDINATION.md](GRAPHICS_COORDINATION.md) и [GRAPHICS_REVIEW_REGISTRY.json](GRAPHICS_REVIEW_REGISTRY.json): до изменения сообщить scope/файлы/SHA ведущей и назначенному проверяющему; после одного образца получить конкретный review до тиражирования; перед готовностью нужна независимая визуальная и техническая проверка того же финального SHA. Собственный PASS не заменяет приёмку. Закрытие дня сохраняется, новые серии автоматически не запускать.

Сохранять соседние правки. Не менять механику, AI, баланс, длительности, опорные точки и формат сохранений ради графики. Не выполнять reset/clean. Публикация графического выпуска требует проверки фактической production-сборки, а не только отдельных листов или макетов.

## Как вести изменения OldGold

- Для крупной задачи сначала зафиксировать цель, границы, решения и открытые вопросы, исходный коммит, владельцев и проверяемые условия готовности. Сверить контракт с последними указаниями пользователя. На пересечении веток передать его соседней сессии для поиска противоречий и пробелов до реализации.
- Разбивать работу на небольшие этапы с самостоятельными проверками. Закрывать этап после выполнения его условий готовности. При передаче указывать проверенный SHA, команды и путь к доказательствам.
- Начать с [README.md](README.md) для запуска и команд, [tests/visual/README.md](tests/visual/README.md) для визуального прогона, а по графике и пересечениям веток использовать [GRAPHICS_RULES.md](GRAPHICS_RULES.md) и [GRAPHICS_COORDINATION.md](GRAPHICS_COORDINATION.md).
- Использовать `npm run check` после изменений игровых скриптов и профильные проверки из `package.json`. Повторяемые проверки и сборщики писать на Node.js, если подходящего инструмента ещё нет. Перед слиянием обновить затронутую документацию по фактическому результату.
- Перед публикацией изменений отрисовки прогнать `npm run test:render` и проверить сцену с новой графикой на холодном и повторном проходе, включая отдаление камеры на мобильном профиле. Замерять точный коммит выпуска.

Источник подхода — [From Idea to Codebase](https://plugfox.dev/llm-driven-project/).
